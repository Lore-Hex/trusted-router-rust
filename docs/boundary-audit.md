## Review decisions before implementation

- No `deny_unknown_fields`, production `panic!`, `todo!`, `unimplemented!`, `unreachable!`, or wire-number `as` casts were found. The integer cast is an SDK attempt count; use checked conversion. Trait-object coercions are not integer conversions.
- ChatMessage serialization has only String keys, JSON Values and concrete derived fields; infallibility is an SDK type invariant. Keep an explicit narrow expect allowance naming it. Receipt ASCII/host expectations and bounded slices are locally proved invariants, not discovered external-data panics; eliminate/check indexing or narrowly document the proof.
- Exchange key, userinfo data and optional identity shapes must follow the shared producer fixture. Preserve all unknown fields and allow absent exchange data and null userinfo sub. No public response field types need changing.
- Other non-Option response fields are protocol identifiers/messages/counts or serde-defaulted metadata. No producer evidence here establishes a lying type; preserve the public API. Value payloads (credits, SSE, opaque outputs) remain open. Request/tool/policy fields are not pass-through responses.
- Receipt rv/tier/hash domain defaults are followed by exact allowed-value checks before use; time/event defaults occur only in diagnostics or after validation. They do not convert malformed trust material to success.
- Attestation image fields can default to empty when the other image field is pinned; wrong-typed present fields must error. Validate nonce list elements, and extract exp/iss without defaults (JWT decoding already validates these, but conversion must also be explicit).
- HTTP error bodies are optional diagnostics: retry/terminal decisions exclusively consume status and x-should-retry. Malformed JSON cannot supply or change a body-derived verdict. Public metadata errors also classify the HTTP status. Telemetry is best-effort by contract and ignores malformed policy updates; it does not grant trust.
- Public BTreeMap header fields are retained for source compatibility, converted per layer into HeaderMap before merges. Names/values return typed configuration errors; case-insensitive reserved stripping is already safe. Preserve repeated values within a layer; per-call values replace the default layer. Empty workspace suppression must remove custom workspace headers just like authorization.
- Environment lookups return Option strings with documented opt-out/default semantics; there are no env/header parse unwraps in production. FFI parses JSON and C strings with typed errors; unsafe pointer validity remains the caller's documented ABI contract. Mutex poison recovery is intentional telemetry fault containment.
- No ignored `let _ = serde_json::from_*` was found. Shape extraction in telemetry is observational/best-effort; receipt and JWKS extraction fails closed. SSE consumed error status currently silently defaults on wrong type and needs a typed error.
